# Project Guidelines

hfd is a headless Hugging Face-compatible server in Go. See [README.md](README.md)
for scope and [go.mod](go.mod) for the required Go version and dependencies.

## Code Map

- [cmd/hfd](cmd/hfd) handles configuration and wiring;
  [pkg/server](pkg/server) assembles HTTP and SSH services.
- [pkg/backend](pkg/backend) owns protocol handlers: Hub API, Git HTTP/SSH,
  Git LFS, Xet token endpoints and the internal API.
- [pkg/repository](pkg/repository) owns Git operations over Billy filesystems.
  Git transport and mirror operations prefer native Git on recognized local
  filesystems; missing Git and non-OS storage, including S3, use go-git.
- [pkg/mirror](pkg/mirror) owns mirroring and the Xet data plane.
  [pkg/storage](pkg/storage) holds repository storage; large-file content lives
  separately in Xet storage. [pkg/gc](pkg/gc) owns reclamation.
- [pkg/authenticate](pkg/authenticate) establishes identity, including anonymous
  identity; [pkg/permission](pkg/permission) enforces access through backend
  hooks. [pkg/receive](pkg/receive) defines receive hooks. Authentication alone
  does not authorize an operation.

## Build and Test

Run from the repository root, using the Go version declared in go.mod. The
[Makefile](Makefile) holds the shared entrypoints and CI runs the same targets:

```sh
make fmt-check
make build
make vet
make test TEST_PKGS=./pkg/repository TEST_ARGS='-run ^TestName -count=1'
make test
```

Replace the package and test name with the affected tests; run focused checks
first. `fmt-check` lists files under `cmd`, `hack`, `internal`, `pkg` and `test`
that `gofmt` would change and fails; `make fmt` rewrites them. The last command
is the full CI suite, including [test/e2e](test/e2e). E2E tests run against
local storage and an in-process S3 service, so external S3 credentials are not
needed. Client cases require `git`, `git-lfs`, `hf`, `python3`,
`huggingface_hub` and `hf_xet`. Some missing-client cases skip locally but fail
with `CI` set; report skips rather than claiming full coverage.

## Working Conventions

- Keep changes scoped; reuse nearby implementations and existing test helpers.
  Format changed Go files with `make fmt` and add regression tests for behavior
  changes. Keep local and S3 behavior covered when storage paths change.
- Preserve the shared server composition and permission checks when adding
  routes; test through the assembled server when routing or auth changes.
- [hf-api-status.md](hf-api-status.md) is generated by
  `make update-hf-api-status`. It fetches upstream OpenAPI and rewrites the
  file; run it deliberately for API coverage updates, not routine validation.
